nsite
Browse decentralized sites — Nostr addressing, Blossom-hosted bytes, SHA256-verified.
Enter an nsite address to browse
Accepts npub1…, a NIP-05 identifier like user@host, an nsite://<npub> URI, a registered NSIT name like nsite://titan, or a pasted gateway URL (https://<npub>.nsite.lol/…).
How this panel uses relays
  • Name lookup → a fixed set of NSIT indexer relays (purplepag.es, user.kindpag.es, …). Independent of your read relays.
  • File index + Blossom list → your read relays from Config, unioned with the author's own NIP-65 outbox relays AND a small always-on content fallback (relay.westernbtc.com, relay.primal.net, relay.damus.io — mirrors Titan Browser's fallback set so Titan-ecosystem nsites resolve regardless of your read-relay config).
  • Blob bytes → the author's announced Blossom servers, falling back to a public pool (no relay involvement). SHA256-verified before render.
Strict sandbox. Render frame runs in an opaque origin with no access to the station. The rendered nsite can connect to Nostr relays (wss://) and load its own SHA256-verified bytes — but cannot load external images, scripts, or fonts from the public web. Authors who want nostr.build-style images should republish them through their own Blossom servers; the bytes are identical (content-addressed) and the <img src="/path"> reference resolves via the SHA256-verified flow.
